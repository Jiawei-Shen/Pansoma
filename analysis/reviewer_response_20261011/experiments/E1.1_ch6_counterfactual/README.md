# E1.1: does the trained SNV model use the haplotype path count (ch6)?

Reviewer points: **R1.1** ("pangenome-native" is not supported: the pangenome is used for alignment only, path
information is discarded) and **R1.m2** (path-aware tensors, competing path support); the assembly section also
bears on **R3.3 / R3.4** (off-reference somatic events). Experiment E1.1 of
`../../response_to_reviewers_detailed.md` (section 6), on the final 7fc7396 models of
`analysis/benchmark_7fc7396_20261012`.

Status: **DONE** (2026-10-13): all 18 SNV models x 8 modes finished, no run pending (`results/summary.json`:
`pending: []`). Tables are regenerated by `collect.py` into `results/tables.md` and `results/summary.json`. The
remaining GPU job (the retraining arm without ch6, for RIS) is listed at the end.

## Question

Channel 6 of every tensor cell is the number of HPRC haplotype paths through the graph node that the read traverses
at that column, coded relative to the graph's haplotype count H (`int8-count-haplotypes100`: count H -> 100,
H-1..H-49 -> 99..51, lower counts -> 1..50, exact when H <= 100 and on a square-root scale when H > 100, repeat
visits above H -> 101..127; `indexed_gam_pipeline_v4/candidates.py` `encode_count`). It is the only input that comes
from the graph's haplotypes rather than from the read or its alignment. The network reads it as one plane
(`path_count`), z-scored with the training mean / std stored in the checkpoint (`encode.py`).

If the trained classifier uses this plane, changing it at inference (no retraining) should change the somatic
scores in a consistent direction. This is a test of use, not of benefit: whether ch6 improves the final calls is
the retraining ablation (no-ch6 arm, GPU commands at the end; E3).

## Method

`ch6_counterfactual.py` (one run per job; imports `machine_learning/pansoma_net_v2` as a library, changes nothing in
it):

- **Test tensors** are exactly `predict`'s: `eval_label >= 0` on chr1 (labels 0/1/2 inside the confident region,
  `off_reference_no_truth_match` counted as non), with the checkpoint's `--ignore-reasons` (the partial somatic
  matches) left out. The counts agree with the RIS `predict` of the same checkpoints (section 2 of `results/tables.md`).
- **Threshold** t = the checkpoint's validation recall-0.9 threshold (`val.somatic_at_recall["0.9"]`), the PASS
  threshold of `graph_vcf`. A tensor "is called" when p_somatic >= t.
- **Inference**: `model(x, blocks, scalars)`, softmax; fp32 on a CPU, bf16 autocast on a GPU (as `predict` does
  on a GPU). Part of the modes ran on CPU first, the rest on tequila's GPUs ("How the runs were done" below);
  section 2 of `results/tables.md` checks the base mode against the RIS GPU `predict` of the same checkpoint.
- **Edits** of ch6, in memory, only on cells with a valid value (ch6 > 0; uncovered cells stay 0, every other
  channel unchanged):

| mode | edit |
|---|---|
| `base` | none |
| `all_H` | every valid cell -> 100 ("all H haplotypes run through this node") |
| `train_mean` | every valid cell -> round(training mean of the valid cells): z ~ 0 everywhere, i.e. the plane carries no information (mean imputation) |
| `train_median` | every valid cell -> the training median; skipped where the median is 100 (then it is `all_H`) |
| `shuffle` | ch6 taken from another chr1 test tensor (fixed random permutation, seed 1): the donor's cell where it has a read, else the donor's column median, else its median; the target's coverage is kept |
| `site0_low` / `site0_high` | the site column (50) only: valid cells -> LOW / cells below 100 raised to 100 |
| `site10_low` / `site10_high` | columns 40-60: the same. `site10_high` is `predict`'s off-reference rescue transform applied to every tensor |

  LOW = the median site code (median ch6 of column 50 over the rows that have a value) of the set's off-reference
  test tensors, i.e. the typical value of a node that GRCh38 does not traverse; on the GRCh38-only graph (no
  off-reference tensors) the 5th percentile of the test tensors' site codes. Training mean / median: the valid ch6
  cells of 3,000 random training tensors (chr2-22, labels 0/1/2); their mean is within 1.2 codes of the checkpoint's
  stored mean (section 1).
- **Measures per mode**: per-tensor somatic AP; somatic, germline and non (on- and off-reference) tensors with
  p_somatic >= t; truth level (`metrics.truth_report`: every chr1 somatic truth SNV counts once, by its best
  tensor) TP / FP / P / R / F1 at t; and the same **after a per-tensor PoN**: each on-reference test tensor's GRCh38
  allele (`grch38` of the summary) is tagged with the SNV rule of `scripts/filter_panel_of_normals.py`
  (`record_matches` with the four PoN VCFs of `/scratch/jshen/data/Pansoma/panel_of_normal_VCFs`), tagged tensors
  are dropped and off-reference tensors are left out (rtg does not score unplaced calls). For the base mode the TP
  agree with rtg vcfeval's PASS result after the PoN within 12 in all 18 runs and the FP within 52 in 11 of the 12
  HPRC-graph runs, but not on the GRCh38-only sets (section 2 and "Results" below): the after-PoN F1 here is a
  per-tensor estimate for comparing modes, not the rtg F1.
- **Assembly off-reference somatic SNVs** (HG008T): the SNP keys of
  `pansoma_net_v2_runs/assembly_offref_20260929/offref_somatic.tsv` (HG008-N assembly events whose somatic allele
  giraffe places on a d9 node off the GRCh38 path) that have a tensor in the set, on all autosomes. None of them is a
  training label (their labels are -1 or an ignored partial match). Scored for `HG008_PacBio` and `HG008_ONT` (d9,
  `--assembly`); the final `HG008_Illumina` run is the class-stratified one, which has no `--assembly`. For the d46
  graph the same procedure was redone on d46 (`asm_d46.sh`: giraffe 1.77 of the same `windows.fq` to d46,
  `asm_d46_classify.py`; done, see "Results"); scoring those keys with each d46 run's own LOW and training statistics
  (`asm_scores.py`, tequila GPU bf16, job 405223, 2026-10-15) is done; see "Results".
- **Class-stratified sample** (`ch6_counterfactual_sampled.py`) for the sets whose test tensors are dominated by
  on-reference non tensors (HG008T and COLO829T Illumina: 158 k and 78-80 k; the GRCh38-only sets: 218-414 k test
  tensors): every somatic and off-reference test tensor, at most 30,000 on-reference germline and 20,000 on-reference
  non (seed 0), each sampled tensor weighted by n_class / kept. Counts, AP and false calls are weighted estimates;
  truth TP is exact. With every weight 1 it reproduces `ch6_counterfactual.py` exactly (checked with `--check` on a
  420-tensor run: "identical").

## How the runs were done

Inference only (no training); checkpoints and tensors read only; outputs in
`/scratch/jshen/data/reviewer_experiments_20261013/E1.1_ch6_counterfactual/<run>/` (GRCh38-only runs under
`linear_sampled/<run>/`); job scripts and logs in `tmp/reviewer_cpu_20261013/E1.1_ch6_counterfactual/`. Code: these
scripts on a frozen `git archive` of 41f7830 (`.../E1.1_ch6_counterfactual/code_41f7830`; the `pansoma_net_v2`
behaviour of 7fc7396), because the shared checkout changed under the running jobs (per-dataset BQ / MAPQ
normalization, f2a0e4e, was cbc94a7). The checkpoints are the RIS 7fc7396 ones, so every run uses the BQ / MAPQ /
path-count statistics stored in its checkpoint.

1. **CPU, fp32** (Slurm array 387176, `cf_array.sh` / `jobs.tsv`, general partition, 16 CPUs, batch 64, from 10:25;
   then array 387276, `cf2_array.sh` / `jobs2.tsv`, full and class-stratified runs). Cancelled at 11:46 and continued
   on GPUs.
2. **tequila GPU, bf16 autocast** (array 387375, `cf_gpu_array.sh` / `jobs3.tsv`, `--gres=gpu:12gb:1` on tequila
   (NVIDIA H100 NVL) per task, batch 128; 18 tasks, 11:48-15:11). The scripts resume: a mode whose probabilities the CPU run had
   already written was reused (fp32), every other mode was computed on the GPU. Kept from the CPU runs:
   `HG008_PacBio` (d9) and `HG008_PacBio_d46`: base, all_H, train_mean; `HG008_ONT` (d9): base; `HG008_ONT_d46`: base,
   all_H. Everything else (the other modes of those four runs and all modes of the other 14 runs) is GPU bf16.
3. **Base-mode check** (section 2 of `results/tables.md`): this experiment's base mode against the RIS GPU bf16
   `predict` of 2026-10-12 (same checkpoint, test tensors and threshold). Somatic AP agrees within 0.0047 in all 18
   runs (largest: `COLO829_fiberseq_linear` 0.2832 / 0.2879, `COLO829_Illumina_joint` 0.6926 / 0.6971,
   `HG008_ONT_linear` 0.0202 / 0.0160; the class-stratified runs are weighted estimates), calls at t within 1.1 %
   (`HG008_PacBio_d46` 3,183 / 3,219), truth TP equal or within 3 (606 / 609). The four runs whose base is CPU fp32
   agree as well: AP 0.2333 / 0.2331 (`HG008_PacBio`), 0.2316 / 0.2323 (`HG008_ONT`), 0.3523 / 0.3528
   (`HG008_PacBio_d46`), 0.3264 / 0.3283 (`HG008_ONT_d46`). So CPU fp32 and GPU bf16 give the same results at the
   scale of the effects below (AP changes of 0.13-0.79 on the HPRC graphs), and mixing them within a run does not
   change the conclusions. (`collect.py`'s section-2 caption still says "CPU fp32 here": it is CPU fp32 for those four
   runs and tequila GPU bf16 for the other 14.)

## Results (`results/tables.md`)

**Setup (section 1).** The site code (median ch6 at column 50) of somatic test tensors is 100 in all 12 HPRC-graph
runs (the read's mismatch sits on a node that every haplotype traverses); germline tensors 95-96 on d9 and 74-80 on
d46 (the read follows a population variant node); off-reference non tensors = LOW, 22-36. Training ch6 mean
79.7-97.4 on the HPRC graphs, within 1.2 codes of the checkpoint's stored mean; on the GRCh38-only graph every valid
cell is 100 (mean 100.0, cells at 100: 1.00, LOW = 100). `train_median` is 100 in every run, so that mode was skipped
(it equals `all_H`).

**HPRC-graph models (12 runs: HG008T d9 x 3, HG008T d46 x 3, COLO829T d46 x 3, COLO829T d9 purity-joint x 3),
sections 3-4:**

- `all_H` ("every haplotype runs through this node"): somatic AP falls from 0.1986-0.3523 to 0.0612-0.0870 (HG008T)
  and from 0.6392-0.8291 to 0.3472-0.5158 (COLO829T). Germline tensors called somatic (p >= t) rise 3.50-3.79x (HG008T
  d9), 3.41-4.19x (COLO829T d9 joint) and 6.64-7.57x (d46), e.g. `HG008_PacBio` 4,951 -> 17,327 and
  `HG008_Illumina_d46` 2,542 -> 17,149; off-reference non tensors at t go from 1-23 to 32-1,746. Truth SNVs found at t
  rise only by 15-59 (e.g. 596 -> 611, 1,777 -> 1,836).
- `train_mean` (the plane carries no information): AP 0.0437-0.0661 (HG008T), 0.3293-0.5197 (COLO829T); germline at t
  2.78-7.73x in 11 runs. The exception is `HG008_ONT` (d9): its training mean (80) moves most cells down and every
  class drops (somatic 65 / 663 at t, germline 1,365, 0.27x).
- `shuffle` (another chr1 tensor's ch6, coverage kept): AP 0.0277-0.0428 (HG008T), 0.1921-0.3079 (COLO829T); truth
  SNVs at t fall to 108-304 (HG008T, base 595-626) and 411-1,018 (COLO829T, base 1,320-1,777).
- Site column only: `site0_low` (column 50 set to LOW) leaves 0-56 somatic tensors at t (of 658-1,995; AP
  0.0022-0.1847): the code at one column switches the somatic call off. `site0_high` raises germline at t
  3.41-9.26x. Columns 40-60: `site10_low` 0-33 somatic at t; `site10_high` germline 3.32-7.31x.
- **After the per-tensor PoN** (section 4, last table) the loss is much smaller, because the PoN removes most of the
  extra germline calls that the edit lets through: `all_H` changes F1 by -0.016 to -0.063 on HG008T (e.g. `HG008_ONT_d46`
  0.579 -> 0.516, `HG008_PacBio` 0.621 -> 0.566) and by -0.042 to +0.007 on COLO829T (`COLO829_Illumina_d46` 0.784 ->
  0.791, `COLO829_ONT_joint` 0.706 -> 0.664); e.g. `HG008_PacBio` after-PoN FP 583 -> 791 while germline at t went
  4,951 -> 17,327. `shuffle` stays costly after the PoN: 0.212-0.421 (HG008T) and 0.274-0.551 (COLO829T). ch6 and the
  PoN carry overlapping information (how common the read's allele / node is in the population); how much ch6 adds
  to the final calls is a question for the retraining arm (end), not for these inference-time edits.

**GRCh38-only models (6 runs), negative control.** ch6 is constant (H = 17, every valid cell 100), so every edit is
the identity and all 8 modes reproduce the base numbers exactly (e.g. `HG008_PacBio_linear` AP 0.0114, after-PoN F1
0.579 in every mode): the edit code changes nothing but ch6.

**Assembly off-reference somatic SNVs (HG008T, d9, section 5).** All scored keys are off-reference tensors (112 in
`HG008T_PacBio`, 89 in `HG008T_ONT`; 8 each on chr1). As trained, the models call almost none of them: base 0 / 112 (PacBio)
and 1 / 89 (ONT) at t (argmax somatic 0 and 1). With ch6 at H they are called: `all_H` 61 / 112 and 49 / 89 at t
(argmax 44 and 49; chr1 5 / 8 and 4 / 8); `train_mean` 30 / 112 and 5 / 89; `shuffle` 19 / 112 and 23 / 89;
`site0_high` 40 / 112 and 39 / 89; `site0_low` / `site10_low` 0. `site10_high` is the edit of `predict`'s off-reference
rescue (`--offref-site90 10`: off-reference SNV tensors re-scored with ch6 raised to 100 at site +- 10 and called by
argmax, `offref_call`, which `graph_vcf` uses): 45 / 112 and 45 / 89 at t, argmax 32 / 112 and 46 / 89, i.e. the
pipeline's own off-reference calls. So ch6 suppresses off-reference somatic events, and the rescue recovers part of
them. On d46 (`asm_d46_classify.py`, job 387185): 345 HG008-N assembly events are off-reference somatic on d46 (154
SNP, 106 INS, 85 DEL; 14 SNPs on chr1); of the 450 d9 off-reference events, 149 stay off-reference on d46, 190 become
on-reference (A) and 94 graph branches (C). Scored by the d46 models (`asm_scores.py`, job 405223; section 5 of
`results/tables.md`), the same suppression holds on d46: at the PASS threshold the base models call 4 / 135
(Illumina), 1 / 82 (PacBio) and 4 / 67 (ONT) of the keys with a tensor; with ch6 set to H 97 / 135, 59 / 82 and
49 / 67; with the rescue edit (site10_high, argmax) 80 / 135, 38 / 82 and 40 / 67. These keys are assembly-derived and
were not read-checked (see `offref_negatives_20260929`: many off-reference keys are germline haplotypes in repeats).

**ch6 alone (section 6, `profile_auc.py`, no model).** The site code alone separates somatic from germline test
tensors with AUC 0.831-0.865 on the 6 HPRC v1.1 runs (3 HG008T d9 and 3 COLO829T joint; medians 100 / 95-96), 0.885-0.915 on
the 6 HPRC v2.1 d46 runs (100 / 74-80) and 0.500 on the 6 GRCh38-only runs (all 2026-10-15, 18 runs); fewer distinct codes in columns 40-60: AUC 0.803-0.842 (all 12 graph runs); fewer cells below 100:
0.627-0.675.

**Per-tensor PoN against rtg (section 2).** After the PoN, the per-tensor TP is at most 12 below rtg's in every run
(e.g. 1,315 / 1,327 `COLO829_ONT_linear`); the FP agree within 52 in 11 of the 12 HPRC-graph runs (not
`COLO829_ONT_joint`: 399 / 595) but are far below rtg's on the GRCh38-only sets (e.g. 837 / 1091
`HG008_Illumina_linear`, 211 / 2216 `COLO829_Illumina_linear`, 1,063 / 2575 `COLO829_ONT_linear`); the cause is not
established. Mode-to-mode comparisons use the same per-tensor rule throughout and are unaffected; rtg F1 values for
the response come from `analysis/benchmark_7fc7396_20261012`.

**What this supports.** The trained HPRC-graph SNV models use the haplotype path count, strongly and in one
direction: a read allele on a node that every haplotype traverses (code 100) reads as somatic, a population variant
node (lower code) as germline. Removing that information (`train_mean`, `shuffle`) or claiming every node is fully
shared (`all_H`) costs 0.13-0.64 somatic AP, and `all_H` multiplies the germline tensors called somatic 3.41-7.57x
before the PoN. This is
information from the graph's haplotype paths, not from the read or its alignment (R1.1, R1.m2). The same mechanism
suppresses true off-reference somatic SNVs (0 / 112, 1 / 89), which `predict`'s rescue partly recovers (32 / 112,
46 / 89 by argmax) (R3.3 / R3.4).
